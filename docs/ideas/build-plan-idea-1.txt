here is a concrete feature list, architecture diagram, and 4-week build plan for Workflow MRI, shaped as a flagship portfolio project that feels credible, polished, and hireable. The design emphasizes workflow diagnosis, governance, and auditability, which aligns with the direction AI is moving toward: tool-using systems embedded in real operations.

Feature list
Core user features
Upload messy operational artifacts: CSV, XLSX, PDF, screenshots, email exports, and notes.

Auto-detect document type, process context, and extraction confidence.

Reconstruct workflow steps, owners, and handoffs.

Identify duplicates, bottlenecks, missing fields, and repeated loops.

Generate a process map with swimlanes and decision points, which is a standard way to clarify ownership and flow.

Produce a cleaned data model with typed entities and validation rules.

Flag privacy, policy, and quality risks.

Queue uncertain items for human review.

Recommend automations with estimated time savings.

Export audit logs, a handoff packet, and implementation backlog items.

Flagship “wow” features
Side-by-side before/after workflow comparison.

Interactive bottleneck heatmap.

“Why this was flagged” evidence links.

Governance panel with approvals and override history.

Simulated ROI/time-savings calculator.

Exportable case-study mode for portfolio presentation.

System architecture
Here is a practical architecture that is simple enough to build but strong enough to demonstrate real engineering judgment.




Layer breakdown
Ingestion Layer. Accepts files and metadata, normalizes them into a single artifact store.

Text + OCR Extraction. Converts PDFs, screenshots, and scans into structured text.

Entity and Step Extraction. Pulls out people, dates, tasks, approvals, systems, and exceptions.

Workflow Graph Builder. Builds a directed graph of how work moves.

Rules + Risk Engine. Detects missing approvals, PII, control gaps, and low-confidence outputs.

Automation Recommender. Scores candidate automations by effort and value.

Human Review Queue. Surfaces anything ambiguous or sensitive.

Audit Log Store. Tracks decisions, overrides, and evidence.

Dashboard + Export Layer. Produces the final visual narrative and downloadable artifacts.

This architecture is strong because it shows both product thinking and operational discipline. It also fits the “governance layer” pattern that enterprise AI teams care about.

4-week build plan
Week 1: Foundations
Define the fake company scenario.

Create seeded sample files and records.

Build ingestion UI.

Set up storage, metadata, and document preview.

Create the basic project structure and navigation.

Week 2: Extraction and graphing
Implement OCR/text extraction.

Build entity and step extraction pipeline.

Convert extracted steps into a process graph.

Render the workflow map.

Add confidence scores and manual correction UI.

Week 3: Governance and recommendations
Add risk detection rules.

Build review queue for uncertain items.

Create automation scoring logic.

Add impact/time-savings estimation.

Store audit events for every significant action.

Week 4: Polish and presentation
Build the operations dashboard.

Create export package generation.

Add before/after comparison view.

Write case-study copy and project narrative.

Polish the UI, transitions, and sample data.

Record a short demo video or GIF sequence.

That schedule keeps the project focused and finishable while still allowing it to feel substantial.

Demo script
